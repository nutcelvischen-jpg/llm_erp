# Demo 講稿（15 分鐘）

對象：老闆、財務、業務、採購主管。重點：**全部在公司這台 Mac 上跑，資料不出公司**；回答有證據（表格、SQL、文件頁碼）。

## Demo 前 10 分鐘：暖機檢查

```bash
make up                 # Postgres + Qdrant
make llm-up             # 聊天與 embedding 兩個模型常駐（lms ps 要看到兩個）
make dev                # http://localhost:8000
curl -s localhost:8000/health   # "ok": true，且沒有 warnings
```

1. 確認 LM Studio 只載入本專案的兩個模型（`lms ps`），其他模型先卸載，避免搶記憶體。
2. **預跑一次 6 題**（點範例按鈕即可）。第一次查文件要載入 reranker，約 10 秒；之後 3–9 秒。
3. 重新整理網頁，清掉預跑的對話，從歡迎畫面開始。
4. 關掉通知、把瀏覽器放大到 110–125%，讓後排看得到表格。

## 流程

| 時間 | 段落 | 做什麼 |
|---|---|---|
| 0:00–2:00 | 開場 | 一句話：「這是在公司內部跑的 AI 助理，可以問 ERP 數字、問合約與規章，還會每週主動提醒呆滯與缺料。」強調沒有連外網 API。 |
| 2:00–9:00 | 6 題問答 | 依下表點範例按鈕，每題講 1 個重點。 |

| 13:00–15:00 | Q&A | 現場讓老闆自己問一題（先準備備援題）。 |

## 6 題與預期畫面

> 假資料的日期以「seed 當天」為基準（`make seed`；可用 `SEED_TODAY=YYYY-MM-DD` 固定），所以金額會隨 seed 日期變動，劇情不變。下表數字是 2026-10-31 從零重建後的實測值，Demo 前預跑時請以當天畫面為準。截圖見 `docs/screenshots/demo_1.png`～`demo_6.png`。

| # | 問題（範例按鈕） | 類型 | 預期畫面 | 講稿重點 |
|---|---|---|---|---|
| 1 | 今年到目前為止毛利跟去年同期比怎樣？哪個客戶掉最多？ | 數字 | 結論「今年毛利比去年同期少 857,507 元，鴻遠機械掉最多（-729,024）」；表格第一列為「（全公司）」，下面是下滑最多的客戶；毛利率 25.9% → 24.5% | 原料成本上漲讓毛利率掉約 1.4 個百分點；鴻遠機械 6 月起訂單驟減。點開 SQL：每個數字都查得到出處。 |
| 2 | 哪些客戶的應收逾期超過 60 天？金額多少？ | 數字 | 台陽科技（3 張，241,643 元）、精興金屬（1 張，32,597 元） | 台陽科技有 3 張逾期 60 天以上，業務該去追了。 |
| 3 | 鴻遠機械的合約，延遲交貨罰款怎麼算？ | 文件 | 條列：每逾一日 0.3%、上限 10%、可自貨款扣抵；來源「銷售合約_鴻遠機械.pdf 第 2 頁 › 第五條」 | 不用翻合約；點來源看原文片段與頁碼。 |
| 4 | 哪些料號超過 180 天沒動？壓了多少錢？ | 數字 | 12 個料號，合計 2,902,034 元；最高 CUS-008（1,576,869 元）；表格含 BRG-6205-2RS | 合計由程式加總，AI 不自己算數字。 |
| 5 | 依目前待出貨訂單，哪些料號會缺料？建議採購多少？ | 數字 | 3 個料號：FST-M8x30-HEX 建議 9,581、GEAR-M2-40T 建議 819、BRG-6204-2RS 建議 722；含供應商與交期 | GEAR-M2-40T 供應商交期 28 天，要馬上下單。建議量 = 缺口 + 安全庫存。 |
| 6 | 員工加班費怎麼計算？依據哪份規章？ | 文件 | 依《人資_工作規則與加班費辦法》：時薪 = 月薪 ÷ 240、倍率（平日前 2 小時 1.34 倍…）、30 分鐘為單位；附來源頁碼 | 人資問題也能問，同一個入口。 |

查數字的回答上方有「標準查詢：同期比較」徽章與參數標籤（期間、對象、筆數…）：**要執行的 SQL 是公司寫死的既定程式，AI 只負責聽懂問題、挑程式、填參數、讀結果**。點開 SQL 可以看到綁定的參數值。

### 加演：問一題沒有既定程式的問題（1 分鐘）
輸入「各業務員今年的毛利率跟去年比」。系統不會自己寫 SQL，而是列出最接近的既定程式（同期比較），並提醒「指標不支援毛利率，改用營收」，按「執行這個」才查；按「都不是」會記錄下來，日後做成新的既定程式（`app.unmatched_questions`）。
講稿：「AI 不會亂查。沒有把握時，它會先問你。」

## 每週預警（手動觸發）

```bash
curl -s -X POST localhost:8000/admin/jobs/dead_stock/run | python3 -m json.tool
```

講稿：「每週一早上 8 點自動跑，這裡手動觸發給大家看。」訊息內容：呆滯 12 項與金額合計、最高 CUS-008；缺料 3 項與建議採購量；下方附完整料號明細。
（LINE 推播目前未設定；設定方式見 `docs/LINE_SETUP.md`。）

## 可信度展示

- **SQL**：寬螢幕右側面板預設展開，可複製。查詢以唯讀帳號執行，只能讀 4 個 View。
- **來源**：文件回答的每句話標 [來源 n]，展開可看檔名、頁碼、原文片段。
- **數字檢查**：AI 回覆中的數字必須出現在查詢結果或程式算出的合計中，否則改用固定句型。
- **稽核**：`http://localhost:8000/admin/audit?limit=10`、`/admin/stats`（今日題數、平均延遲、各類型數量）。

## 常見失敗與備援

| 狀況 | 處理 |
|---|---|
| 第一題轉很久（>15 秒） | 沒暖機或模型被卸載。`lms ps` 確認兩個模型都在；不行就 `make llm-up` 後重問。 |
| 回答出現紅框「這部分查詢失敗」 | 看訊息：連不上資料庫 → `make up`；LLM 逾時 → 確認 LM Studio Server 為 Running。 |
| 查數字的回答是很制式的一句話 | AI 結論沒通過數字檢查，系統改用既定程式的固定句型；數字仍正確，照表格講即可。 |
| 範例問題出現「您是要查下列其中一個嗎？」 | AI 沒有十足把握，點最上面的「執行這個」即可；也可以順勢展示這個保護機制。 |
| 老闆問了不支援的問題（薪資、競爭對手） | 系統會婉拒，順勢說明「資料庫沒有薪資資料，這是權限設計」。 |
| 文件問題回「依現有文件查無相關資料」 | 換成指名對象的問法（例如加上客戶名稱或規章名稱）。 |
| 網頁打不開 | `make dev` 有沒有在跑、port 8000 是否被占用。 |
| 現場臨時要問 | 備援題：「台陽科技逾期的應收有多少？依合約逾期多久可以暫停出貨？」（同時查數字與合約）、「GEAR-M2-40T 的材質與硬度？」、「鴻遠機械今年營收多少？」再追問「那去年呢？」（展示對話脈絡）。 |
